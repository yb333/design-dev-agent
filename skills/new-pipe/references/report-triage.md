# 上报分诊手册（engineer 第一响应人的方法库）

> 收到任何子 agent（designer/coder/dq-producer）上报时读本手册。原则在身份层（agents/dws-engineer.md）：
> **永不裸转发——至少一步增值**。这里给方法：核实用什么、怎么归类、怎么分级、怎么路由。

## 一、四步协议与工具映射

| 步 | 干什么 | 工具（按上报类型选） | 成本 |
|---|---|---|---|
| ① 核实 | "子 agent 说"→"实测说"（上报自带实测数字时此步免费，别在这停） | check_field（字段存在性/类型）/ explore --where（键唯一性带条件验）/ 复现命令（报错类重跑一遍） | 秒-分钟 |
| ② 诊断方向 | 归类四类 | 对照分流表 + ①的实测结果 | 判断 |
| ③ 影响实证 | 跑出"实际造成什么"——**关联类疑点必跑边级试算**（评估期 `diagnose_fanout --edge`，有 ts 时 `--rule`）；其余类型对应三档（阻塞交付/可绕过留痕/仅信息性） | diagnose_fanout --edge / --rule | 分钟 |
| ④ 路由 | 语义/输入类→带四件套问人；确定性技术回路→直接走（分流表内，不问人） | 分流表（AGENTS「质检与分流」） | — |

问人材料四件套：**实测事实**（①的数字/结论）+ **根因方向**（②的归类）+ **影响实证**（③a 的 --edge 试算结论/③b 的粒度性质说明/其余分级）+ **选项**（每项含后果）。**③a 类疑点的"影响实证"字段空着=材料不合格——先跑 --edge 再问人（无试算结论进材料=裸转发）**。材料可**引用** RS 数据探索事实（量级/空值率——现成输入事实，是人选收敛/接受的重要上下文），不做主动展开分析。

**选项以选择题形态给出**（人只选编号，选项的落盘 reason 由你标准化代笔）；人写了自由文本=另一条路——按回答内容自由决策，**不硬套模板**（可能本质是修/接受/全新口径，模型据实理解处置）。

轻重分级：
- 字段不存在类上报 → check_field 一查即核实（秒级，最轻）
- 键不唯一/疑点清单 → explore --where 逐条验（剧本已有实例流程）
- 报错类 → 复现命令重跑（区分可复现=真问题 / 不可复现=环境瞬时）
- 环境类（连不上/权限） → 不用核实直接路由归人

## 二、固定套路表（recipe——照表执行零思考，步骤跑完即路由禁加戏）

> 诊断结论只有几行字，开放式推理烧轮次烧上下文（内网实证：后续执行任务的上下文被低价值诊断挤占）。
> 遇上报先查表匹配类型 → 照步骤跑 → 按模板出结论 → 路由。工具长输出已落盘（_internal/diagnose/ 等），
> 主线只引结论两行。新套路随真实案例沉淀进本表。

### 套路 R1：关联发散/键不唯一【封顶 2 步——按有无 ts 选试算形态】
1. 复核实测（确认不唯一数字——防误报/参数错）：评估层上报自带 --eval 实测数字，复测一条即可（explore --check-join-key 或 --eval 事实行直接用）
2. **影响试算**（人拿"当前命中面"和拿"可能发散"是完全不同的决策——这步不可省）：
   - **评估层（无 ts）**：`diagnose_fanout --rs {rs} --edge`（**零参数直接跑**——自动试算落盘全部"从表键不唯一"疑点，逐边结论合并落盘；表/键/限定/对侧全派生，对侧键=关联条件配对列；单疑点复测才 --doubt，链式边 --partner；主表疑点自动拒指③b；参数手传需 --override 走同一存在性闸）
   - **UT/闸口①（有 ts）**：`diagnose_fanout --rule <规则>` 整体试算（主表实际膨胀与否）
   - 自然语言边双边构造不出 → 材料明写"链路影响未实测，终局归闸口①实证"，不硬猜不自建脚本
3. 结论模板（两行）：`键在限定条件下不唯一（X 行重复）；当前命中 K 组/整体当前膨胀 N 行` / `当前零膨胀（=发散键未命中，未来命中即膨胀——风险披露，非安全信号）`
→ 路由：两行结论+实测数字给人（选项三态：**修源端**（退 BA——修数据/修口径/**定收敛口径**，收敛决策归源端我们只做技术实现）/ **采纳已声明条件**（mapping 声明过限定、设计漏采纳——试算验证有效后补进 join，技术补全）/ **知情接受**（试算证明当前不影响主表粒度，零改动——裁决回写 join_safety 留痕））。**禁再加戏**（多查一层"为什么不唯一"=源数据问题归人，不是你的事）

### 套路 R2：字段/表不存在【1 步到顶】
1. `check_field --field <别名.字段>` 查一次（秒级；表级用 schema_query）
2. 结论模板：`字段 X 不在表 Y（上报属实）` / `系拼写差（相近字段：Z）`
→ 路由：**直接给人**（人立刻知道是 mapping 错还是引用错）——不要展开"为什么 mapping 会错"之类，那是人的领域

## 三、上报类型实例

### designer 疑点清单（评估层上报——评估结果=join_safety 事实行+疑点清单+疑似方向，⚠ 阻塞首行，**预期产物非异常**）

先分型（每型做实路径不同，做实后统一攒批问人）：

| 疑点型 | 例子 | engineer 做实 | 归处 |
|---|---|---|---|
| ①声明缺失 | 条件引用字段 mapping 没写 | 查 mapping 原文证实 | 人选项 |
| ②声明不符 | 声明 code 库里只有 cod_cf | 查 mapping+cache 摆清差异 | 人选项 |
| ③a 从表键发散 | 从表键限定下不唯一 | R1 套路（复测+--edge 边级试算，**结论必带**） | 人选项 |
| ③b 主表粒度线发散 | 主表业务主键不唯一/未确定 | **无边可试算，不跑 --edge**——材料直接带选项：补键[复合]/退BA修数据（收敛口径归源端，设计侧不自主发明） | 人选项 |
| ④口径不全 | "取最新"没说按什么分组 | 不可验 | 直接给人 |
| ⑤`?` 未答 | 原文对不出物理名 | **查 mapping——找到=自答**：Task 带 task_id 恢复 designer 续跑（不问人）；真没有=给人 | 自答 或 人 |

→ 影响：不解决则设计建立在发散假设上（阻塞）→ 路由：**攒批一次 question**（疑点全列齐四件套：实测事实/根因方向/影响[③带 --edge 结论]/选项），人答复路由：**修源端** → 终止本轮（输出终止报告：事实+人的选择+重启条件[源端修正后重跑步骤 1]，评估层设计作废是预期内）｜**采纳已声明条件** → 带**裁决**恢复 designer 会话（只带裁决不带试算分析，designer 补条件进 join）｜**知情接受** → 带裁决恢复（designer 落 join_safety 该关联 `unique=false + reason="试算不影响主表粒度，人判知情接受"`——闸口① diagnose --all 已知接受不重复弹，档案留痕）｜**自由文本** → 按回答内容自由决策（不硬套模板）。

### designer 终止型（输入/源端要修）
核实：对照 rs_input 原文确认缺口真实（它说 mapping 没有→查 mapping 确实没有；防它没读到/读错段）→ 诊断：输入问题 → 影响：输入一变 view 重建、手头设计作废（阻塞） → 路由：question 一次（选项给完整后果：终止本轮 vs 继续型出路），终止则输出终止报告（事实+人的选择+重启条件）。

### 阻塞上报（首行 ⚠ 标记——子 agent 无 question，答不了就停）
核实：看它阻塞的点是否真实依赖（有时可自行回答——契约参数/剧本/既有材料里有的答案直接带上）→ 能答：恢复会话带答案续跑（**恢复=再发 Task 同 subagent_type + 起 Task 时记录的 task_id**，会话带全部前文，不新开不丢上下文）；不能答且属语义：问人后带回 → 影响：不续跑该会话即停工（阻塞）。

### coder 口径疑义（design_logic 矛盾/表达式跑不通）
核实：对照 ts 的 design_logic 原文+mapping 原文（两者谁矛盾）→ 诊断：designer 翻译错（回 designer）vs mapping 本身矛盾（退源端）→ 影响：coder 停写该规则（局部阻塞） → 路由：按诊断归口，材料带两侧原文。

### DQ producer FAIL/ALERT
FAIL（SQL 执行错）：核实看报错分类提示（报告已带）→ 技术回路直接恢复 producer 修（限 3 轮），不问人。
ALERT（非 0 行）：**攒闸口②一次人判**（三选一：回改/人定口径或取消/豁免），不在中途弹人——零自动回路防空转。对比式 0 行=双义提示进闸口②材料。

### 环境类（连库/权限/缺表/超时）
不核实直接路由：停下+报告修复指引给人。

## 四、红线边界（本协议不改变的东西）

- 语义判断仍归人（L3）——你的四步是把事实备齐，不是替人定罪
- 设计变更必回闸口①——诊断出设计问题也不私下改
- 分流表外的问题默认上报人——四步走完仍归不了的，给人
