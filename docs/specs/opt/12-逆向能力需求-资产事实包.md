> 定位：我们对逆向项目的**完整需求基线**——只提要求，不提方案（判型/解析/架构全归逆向侧）。
> **v3 基线已实施**（facts 服务：`run.py facts --dir <制品目录> --output <产物路径>`，产物 asset_facts.json v1.3）。本文 **v3.1 增量**=交付门模型（2026-10-14 与消费方定稿）：逆向产物落消费方指定暂存区、审核确认后建档——档案只经确认诞生。

## 一～六：v3 基线条款（已实施，不变）

接口两路径 / 输入识别职责（混放不拦·.sql 归 DDL·DQ 两态）/ 产物 asset_facts.json 与四纪律 / 验收告知 / 失败语义 / 演进波次——全文见文末存档节或对接文档 docs/14。以下为**增量条款**。

## 七、产物落盘位置与交付形态（增量）

1. 产物落盘路径由调用方经 `--output` 指定——消费方固定指向**逆向暂存区**（`{ddlc}/reverse/`，消费方目录模型的一部分；**随时可删可覆盖重跑，不参与任何路由判断**）。此项你们零改动，仅告知背景。
2. **产物总是落盘**——即使检出结构级矛盾（§八）也照常产出（排查全景材料：消费方的人审要看"逆向到底解析出了什么"）。"通过与否"不体现在产物的存在性上。

## 八、自检结论三态（增量，核心）

产物交付时必须携带**自检结论**，三态：

| 结论 | 语义 | 消费方动作 |
|---|---|---|
| **通过** | 干净或仅噪音级差异 | 直接进审核对账 |
| **通过（带噪音清单）** | 存在噪音级 warnings（登记滞后类常态差异） | 对账过 → 建档，清单进闸口材料披露 |
| **待审（结构级清单）** | 存在结构级矛盾（见 §九分级） | 审核动作拦下 → 人审（换料重跑 / 显式放行） |

- 携带形态你定（产物元信息字段 / stdout 结论行 / 参数化皆可）——要求：机器可判读、三种状态可区分；
- **退出码语义不变**（0 成功/1 制品数据问题/2 参数错）——"待审"不是失败（exit 0 + 待审结论），人审放行后才算过。

## 九、warnings 严重度分级（增量）

- warnings 须带**严重度标注**，至少两级：**结构级**（指向"料可能给错/资产级对不上"：如 DDL 表与术加目标表不符、LTS 任务引用无关表、DDL 内部表冲突）与**噪音级**（平台常态差异：登记滞后等）；
- 分级口径你定（你是制品域知识的权威）；分级错误的代价消费方评估过：误升（噪音判结构级）→ 流程停一次人放行，低成本可接受；误降 → 消费方审核对账与闸口还有两道眼兜底；
- 分级驱动两个消费点：§八的待审判定 + 闸口材料的高亮（结构级置顶、噪音级折叠）。

## 十、制品间一致性交叉（增量）

同资产多类制品之间的一致性校验归你（两边料与判定知识都在你侧；差异=存量既成事实，**披露不阻断**）：

| 交叉 | 对什么 |
|---|---|
| 术加 TargetFields vs RULE SQL | 字段登记 vs 投影（已有 field_name_mismatch——确认覆盖） |
| 术加 vs DDL | 目标表存在性 + 字段集差异 |
| 术加 vs LTS | 调度任务引用的表与制品目标/源表对应性 |
| 术加 vs DQ | DQ 规则目标表与制品目标表 |
| DDL 内部 | 多 .sql 的表重复/冲突 |

- 差异逐条**可读可定位**（哪个制品哪个位置、差什么）——消费方闸口给人扫；
- 结果进 warnings（带 §九分级）。
