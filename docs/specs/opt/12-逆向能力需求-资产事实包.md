## 一、调用场景与接口（收窄）

我们的优化管线发现资产无档时发起逆向，此后拿产物入料建档。接口就两个路径：

| 项 | 要求 |
|---|---|
| 输入 | **一个制品目录路径**（该资产的全部原始制品；内容见 §二） |
| 输出 | **一个产物落盘路径**（asset_facts.json，见 §三） |
| 调用形态 | 命令行直接入口（参数怎么设计你定）——**我们不构造 manifest/清单等任何中间结构**，那是你的内部事务 |
| 交卷 | 一次调用一次交卷；我们不做反复调用 |

**资产标识不传**：防串包由我们验收侧对账（§四），你无需为此校验（内部要不要留随你）。

## 二、输入形态与识别要求

1. 输入=一个目录。文件命名、目录组织、**混放非制品文件**（mapping/RS/说明文档等与制品同目录）零要求。
2. 期望内容：**术加制品包 excel 必需**（没有它无法产出）；LTS / DQ / DDL 可选（各什么时候该有见第 5 条）。
3. **每个文件是什么类型，识别职责全在逆向侧**（我们不指认、不猜）：
   - **必需料缺失或判不出 → fail loud**（报清楚缺什么料/哪个文件差什么特征）；
   - **无法识别的文件不阻断主流程**：逐个列出、随产物交付（进 warnings 一类通道），由我们在闸口给人扫一眼——只有必需料（术加）判不出才整体 fail。〔修正 1：当前 excel_dir 把 mapping（非制品 excel）也当"无法识别"拦停——用户把 mapping 与制品放同一目录是常态，不应被拦〕
   - **`.sql` 文件自动视为 DDL 收录**（后缀即型，无歧义），不算"无法识别"。〔修正 2：当前 .sql 被报无法识别〕
4. **DQ 语义（目录通道=两态）**：检出 DQ 制品 → 有（dq_rules 列表）；**未检出 → 无**（dq_rules=[]，且产物元信息标注"未检出 DQ 制品"——我们闸口据此向人披露纠错）。**不要求调用方显式声明"无"**——目录就是用户给的全部，"忘了给"由我们闸口人扫兜底，不前置停等。〔修正 3：当前未检出仍要求显式 declared_absent〕
5. LTS 的到位要求（供你侧报错参考）：增量资产的制品里应有 LTS（增量变量还原是回刷地基）；变更触碰调度时（新来源表/回刷/DQ 任务）也应有。缺了属"输入料不全"，报出来即可，是否阻断你按"必需/可选"自行判断。

## 三、产物要求：`asset_facts.json`（原 baseline_v1.json **更名**）

1. 落盘到指定输出路径；**stdout 打一行产物绝对路径**（我们解析定位）。
2. 内容=存量资产的**物理事实包**（名字即定位）。必须覆盖我们的消费面（字段结构以双方契约 schema 为准——schema 权威在你仓，变更走 §六波次）：

| 消费点（我们管线哪里用） | 必须有的信息 |
|---|---|
| 基线组装（设计开工的地基） | 每规则的 SQL 原文 / 写入方式 / 目标表 / 源表清单 / 表与字段（含 DDL 物理属性：分布键、分区） |
| 变更围栏（冻结层比对） | 字段集合、字段血缘表达式、SQL 原文——**全部逐字** |
| 新老双跑（老列逐值一致） | SQL 原文（我们的对比基准） |
| 增量/回刷 | 写入条件、调度任务与参数（含增量变量） |
| 制品 patch 定位 | 每个制品的定位信息（哪个文件哪个 sheet/页） |
| 设计师理解存量 | 关联条件/过滤条件等结构化事实 + 交叉验证差异清单（warnings） |
| 完备性自证 | 契约版本号 + "拿不到的事实"显式空并进 warnings |

3. **四条产出纪律**（行为要求，沿用既有约定）：逐字保真（SQL/表达式/条件逐字节，禁美化重排）；显式空（拿不到=null/[]，不省略 key）；自校验全绿才落盘（交卷即终态）；一次产全（漏项只能显式空+warnings，此后我们不回头再问）。
4. **语义判断永不进产物**：增量字段、驱动表、主键、粒度——哪怕解析时能推测。
5. DQ 部分带**平台规则编码**（存量规则的稳定标识——我们 DQ 制品重建时沿用，防平台重复建规则）。
6. 可选并行产物：存量资产的 spec 草稿（给我们上游 RS 段）——不进我们管线，交付形态你与 RS 段自行约定。

## 四、验收（我们侧，告知性条款）

产物过我们的校验链，任一不过 fail loud 退回：版本支持 → 契约 schema → 内部一致性（SQL 引用的表 ⊆ 声明源表、血缘目标 ⊆ 表字段）→ **资产对账（产物中的资产标识 vs 我们从变更输入推出的资产——不一致=串包，拒收）**。

## 五、失败语义

- 成功：exit 0 + 产物落盘 + stdout 定位行。
- 失败：exit 非 0 + **产物不落盘** + 错误清单**可行动**（哪个文件、什么问题、缺什么料——我们能据此向人要料或退回）。
- 任何情况不代填、不编造后重跑。

## 六、版本与演进

- 契约 schema 权威在你仓，我们 vendor 跟随；**变更波次**：你先行（schema+契约文档+fixtures+version bump）→ 我们跟随（vendor+消费端适配+契约测试绿）→ 同一波内双仓各自同步内网。
- **本次更名**（baseline_v1.json → asset_facts.json）随下一波契约版本一起生效；过渡期版本兼容由 version 字段机制约定（我们支持读取旧名产物到波次切换为止）。
- 部署：你的 skill 成品已纳入我们的双源内网同步（一次同步两仓就绪，见我们仓 SYNC-GUIDE ⓪节）——你无需自建内网通道；运行环境依赖清单随 skill 走，我们不为你装包。
