# 06 · 验证段（UT + 输出对比）

> 第6章定稿（v1.9）。双跑的落地形态 = **UT 的一类检查项**（与主键/空值检查并列），不是独立机制。定位：开发环境验证；生产影子表/灰度属需求层，agent 不决策不实现。

---

## 一、UT 骨架与检查项

- **两阶段结构照旧**：6a 预检（秒级）/ 6b 执行（分钟级）。
- 检查项的优化模式版本：

| 检查 | 优化模式处理 |
|------|-------------|
| 主键唯一性 | **豁免**（存量无 business_key 声明；输出对比是更强回归保证——第2章定论落实） |
| 空值检查 | **只对新增列**跑，对照声明 NULL 率预期 |
| 输出对比（★新增） | 双跑的落地形态，见 §二 |

## 二、输出对比检查（双跑落地）

- **输入**：老 SELECT（`etl_baseline/`）+ 新 SELECT（`etl/`）+ change 段的冻结/自由声明。（两来源兼容：档案路径 etl_baseline = 档案 etl SQL；json 路径 = 契约逐字落盘。）
- **实现**：**双向 MINUS 一条 SQL**——两个 SELECT 同库同时执行，`老 MINUS 新` / `新 MINUS 老` 各一次。零临时对象、零快照，天然同数据同时点。（备选的物化影子表方案不采用：多一套对象管理，收益仅样例留存，MINUS 报告同样带样例。）
- **判定（oracle 按声明参数化）**：
  - 冻结列双向差集必须为空；
  - 差异只允许出现在新增列上；新增列 NULL 率对照声明。
- **增量基线**：两个 SELECT 限定**同一增量窗口**再比（窗口内一致性）；跨窗口历史行为归回刷管。
- **互补关系**：MINUS 是 SELECT 级，管不了写路径（目标列类型转换靠行数据触发）→ INSERT 全量执行照跑，**SELECT 对比 + 全量 INSERT 两道缺一不可**（沿用"UT 终审按全量结果"原则）。

## 三、UT 的 DDL 步骤：CREATE 改 ALTER

- ut_precheck 的 DDL 环节在优化模式执行第5章生成的 `alter_table_*.sql`（对开发库已有表加列）。
- **表不存在 = 环境问题归人**（对齐 new-pipe 6c），不自己 CREATE 兜底。

## 四、失败分流：三类照旧，不加第四类

对比失败（老列不一致）归入**数据质量类**，走 new-pipe 6b 既有模式——人看样例定根因：

| 根因 | 去向 |
|------|------|
| 新 JOIN 发散（行数变了老列跟着变）= 设计问题 | 人定改法 → 回 designer → 改完**回闸口①'重确认** |
| 源数据问题（开发库数据脏） | 环境问题归人，不改设计 |
| SQL 报错（COLUMN/TYPE/SYNTAX） | 回 coder（恢复旧会话） |
| 连接/权限/表缺失 | 环境问题归人 |

每规则限 3 轮照旧。

## 五、回刷的验证顺序

选拔回刷的资产：**init（回刷窗口建数）→ 增量**，现有两阶段机制零改造。

**回刷窗口的老列一致性对比：搁置（v2.2 定，用户拍板）**——第一刀不实现（老侧基准需从老 SQL 推导全历史版本，方法已论证可行：与 coder 的 INIT_ derive 同构），真实运行后再评估要不要加。**已知限制显式记录**：回刷场景的回归验证弱于增量窗口场景，闸口②'如实提示。

## 六、闸口②'人审项（原则9 收敛）

呈现 = **两问 + 资产健康提示一屏**（warnings 摘要，第7章）：

1. **新列结果合理性**："新列 NULL 率 X%、值分布摘要——符合预期？"（一屏）；
2. **交付物确认**：ALTER 变更单 + 新 SQL + 回刷脚本（如有）+ 制品 patch 说明（第7章）清单，人确认后流程结束、写回档案。

不问：冻结列对比细节（机器已判零差异才走到这）、全量 diff。
交互对齐现有闸口（question；非交互须显式声明）。
