# 14 · 逆向能力需求：台账视图（mapping 语义重建）

> 读者：**逆向工程侧**。本文档定义逆向的新增产出——**台账视图**——的内容模型与设计原则。
> 台账视图的内容 = 正向链路的 mapping 台账（实体级/属性级字段映射），用于存量资产重建字段级映射当前态。
> **本文档只定义内容必须满足的原则，不定义文件格式**——产出形态（JSON 或其他）由逆向侧设计；
> 信息面以正向 mapping（`docs/specs/mapping-format.md`）为参照概念，不绑定其当前的单场景表格形态，
> 内容模型中场景维度为一等维度（见 §2.4），未来正向台账演进为多场景时无需重构。

---

## 一、这是什么，与 ts 草稿的关系

- **台账视图**：存量资产从制品逆向重建出的字段级映射当前态——每个目标字段从哪些物理源表字段来、
  经过什么加工、表与表怎么关联。消费者：SE/BA 读它理解字段口径并在此之上登记变更；
  优化链路用它做变更对照面。
- **与 ts 草稿的分工**：ts 草稿是知识全量（query_sql 逐字保真 + 分层 design_logic + 结构声明）；
  台账视图是它的**字段级投影**。投影必然有损，损的部分必须在 ts 草稿里有家——
  台账不是第二份独立理解，**两者必须同源一致**（见 P6）。
- **有损投影的合法性边界**：台账不装 ts 草稿的全部细节（分层规则、写入方式、调度），这是设计意图；
  但**行集变换（关联/去重/聚合等预处理）不允许丢**——它们必须在台账有结构化呈现位（见 P4/P5）。
- **物化是实现取舍，台账不可见**：tmp 物化只是实现上的选择（性能/可读性等考虑）；同一段业务逻辑
  无论实现上是否物化，台账必须同形（**物化无关性**，见 P1）。

---

## 二、内容模型：两层登记 + 锚名 + 场景维度

> 下列「信息面」用正向 mapping 的概念名作参照（便于对照理解），**不是格式规范**。

### 2.1 实体级：物理源表登记

每张**物理源表**一条登记，信息面：

| 信息 | 说明 |
|---|---|
| 源表 schema / 物理表名 / 中文名 | 中文名取 DDL 注释 |
| 源表别名 | **SQL 实际别名为权威**（落笔权威，不自创） |
| 关联&限定条件 | 该表参与的 join 条件（逐字取 SQL 的 ON 条件）；主表填说明；逻辑从表对主表的整体关联条件挂驱动表行（见 P4） |
| 取数规则 | 表级预处理说明与片段挂载位（见 P4/P5） |
| 场景分组 | 见 §2.4 |

登记纪律：

- **只有物理表**。tmp/中间表、内联视图/CTE 一律不登记为源表——这是**穿透原则**（P1）。
- **逻辑从表**（台账的核心概念）：主表关联的一个逻辑单元，由一或多张物理表经行集变换组成；
  在代码里可能是嵌套子查询/CTE（未物化）或 tmp（物化）——**台账一律按未物化形态呈现**（内联等价，见 P1）。
- 同一物理表被多次引用（自关联等）= 多条登记，别名区分（正向同款机制）。
- **只参与行集操作、不贡献任何字段值的表**（去重排序依据表、桥表、过滤条件表）照常登记——
  它们的作用通过关联条件与片段表达，属性级无字段行引用它们是合法形态。

### 2.2 属性级：字段映射

一行一个目标字段（多来源的拆分原则见 §4 UNION），信息面：

| 信息 | 说明 |
|---|---|
| 目标字段名 / 中文名 / 类型 | 与 ts 草稿 tables 一致（P6） |
| 源表别名 + 源字段名 | **值血缘根，穿透到物理表**（P1）；多来源用多值形态登记 |
| 映射规则分类 | 分类与表达式形态一致：直取 / 数据加工 / 聚合（词表对齐正向，正向词表待与业务对齐） |
| 映射表达式 | **展开态语义表达式 +（说明段）**，见 P3/P5 |
| 备注 / 场景分组 | 补充说明；不得含 tmp 表名/规则编号/物化事实（物化无关性）、见 §2.4 |

### 2.3 锚名

- 逻辑单元以**引用它的 SQL 别名**作为**引用锚**（如嵌套子查询的别名 `d`；物化场景取引用该 tmp 的
  SQL 别名，**tmp 表名永不出现**）。
- 锚出现在：实体级片段挂载标签（【逻辑从表 d · 定义】）、属性级表达式的说明段（「经逻辑从表 d」）。
- **锚不是源表登记**，且**永不出现在表达式本体的引用位**（引用位只允许物理根别名，见 P3 的可解析性要求）。

### 2.4 场景维度（一等维度）

- 实体级登记与属性级映射都归属某**场景组**；单场景资产 = 唯一默认组（现状形态）。
- 多场景资产（同一目标表按场景区分来源/过滤/产出）= 多组登记并存。
- **UNION 分支按场景组拆登记**（同一目标字段多行，各行各自的穿透与表达式，见 §4）。
- 未来正向台账演进为多场景时，本模型天然容纳，无需重构。

## 三、核心原则 P1–P6

### P1 穿透与物化无关性

- 实体级源表清单与属性级源字段登记，一律**穿透到物理根**：tmp/中间表/逻辑从表既不进源表清单，
  也不作为源字段的登记值。
- **物化无关性（穿透的完整含义）**：同一段业务逻辑，实现上无论是否物化（嵌套子查询 / CTE / tmp），
  台账必须**同形**。物化只是实现取舍（性能/可读性等），不属于台账信息面——台账任何位置不出现
  tmp 表名、规则编号、写入方式。
- 物化场景的压平规则 = **内联等价**：把 tmp 的 SQL 当作逻辑从表的定义，内联回引用它的位置，
  台账按内联后的未物化形态呈现（锚名 = 引用它的 SQL 别名）。
- 穿透跳过的中间层，其定义在实体级有片段挂载（P4），其加工链在表达式有展开呈现（P3）——
  穿透不是删除信息，是分层安放。
- 实务收益：实现重构（子查询物化为 tmp 或反之）不产生台账 diff；台账读者做变更时无需感知物化存在。

### P2 值变换 / 行集变换二分

SQL 里的加工按**作用对象**分两类，各归其位——这是整个内容模型的骨架：

| 类别 | 回答的问题 | 例子 | 归属 |
|---|---|---|---|
| **值变换** | 这个字段的值怎么算 | 运算、函数、case when、聚合函数 | 属性级表达式（P3） |
| **行集变换** | 参与计算的是哪些行、行怎么组合 | 关联、过滤、去重（rn=1）、分组粒度、UNION | 实体级（关联条件 + P4 片段） |

嵌套子查询 = 多层行集变换与若干值变换的交织；拆开后值变换链压成一个展开表达式，
行集变换整块片段挂实体级。

### P3 表达式：各跳原样 + 机械展开到物理根

- **展开定义**：沿血缘链从终态表达式出发，遇到引用中间产物（tmp 字段 / 逻辑从表字段）时，
  替换为其定义表达式；替换**保持各跳文本原样**，仅做变量代入，不改写任何一跳。
- 同聚合层级内可完全代入到物理根：`d.final_rate` → `ab.rate * c.adj` → `a.rate * c.adj`。
- **跨聚合层级**代入后为**语义表达式**（不是可执行 SQL，是口径表达式）：
  `max(a.rate) * c.adj（a 按 k 聚合取最大；经逻辑从表 d）`——聚合函数留在表达式内，
  分组粒度在说明段/片段。coder 消费时按分层实现，语义精确即可。
- **引用位只允许物理根别名**：表达式本体的全部 `别名.字段` 引用必须能在实体级登记中找到
  （消费侧引用门禁的硬要求）；逻辑别名/锚名只出现在全角括号说明段（说明段被门禁剥除不检查）。
- 表达式形态 = `SQL 表达式（口径说明）` 双段，与正向 design_logic 同构，说明段允许为空。

### P4 行集变换：片段整块逐字挂实体级

- **凡穿透跳过的中间层（逻辑从表，未物化或物化），其完整定义 SQL 片段必须在实体级有挂载**，
  保证台账自足（不依赖翻 ts 草稿即可看到全部行集变换）。
- 挂载位：逻辑单元**驱动表**（最内层 FROM 首表）的登记行，标签注明锚名；
  其余参与表行指回（「参与逻辑从表 d，定义见 a 行」）。
- **整块逐字，不拆层**：嵌套再深也是一整块——拆层=解析=引入出错面。
- 片段来源（逐字子串的出处）：未物化 = 所在规则的 query_sql；物化 = 该 tmp 的 SQL——
  同一逻辑两种实现的片段主体相同（物化无关性的自然结果）。
- 片段之外，实体级「关联&限定条件」仍逐字登记各表 join 条件（含逻辑单元对主表的整体关联条件，挂驱动表行）。

### P5 片段为本体，人话为增益

- 有预处理（行集变换）时，**片段是本体（必在），人话说明是增益（可空）**：
  能从片段结构确定性归纳一句口径（「按 k 取生效日期最新一条」）则写入说明段；
  归纳不出就留空，**禁止编造**（宁缺勿错——错的人话比没有更糟，读者会按它做变更判断）。
- 读者有两条阅读路径：说明段快速理解，片段深读。信息永不丢。

### P6 与 ts 草稿同源一致

台账视图与 ts 草稿必须同源一致，一致性面：

- 字段清单 / 字段类型 / 字段中文名 ↔ ts 草稿 tables；
- 源表清单（物理表+别名）↔ ts 草稿 rules 的 source_tables；
- 表达式链上每一跳 ↔ ts 草稿对应层 design_logic / query_sql；
- 片段 ↔ query_sql 逐字子串。

台账表达式是**展开态**、ts 草稿 design_logic 是**分层态**——两者系统性不同形，这是设计选择
（台账对齐读者视角），一致性校验时以「展开后比对」为口径。

## 四、边界场景处理原则

| 场景 | 处理 |
|---|---|
| **跨聚合层级**（中间层是聚合而非去重） | 表达式=语义表达式（聚合函数内嵌，P3）；分组粒度在片段/说明段 |
| **逻辑从表内 UNION** | 同一目标字段按场景组拆多行（§2.4），各分支各自穿透、各自表达式；片段仍整块一份 |
| **同一物理表多次引用**（自关联） | 实体级多条登记，别名区分 |
| **逻辑从表多层嵌套**（d 内还有 e） | 片段整块逐字（不拆层）；表达式展开到最底层物理根；说明段指回最外层锚名 |
| **标量相关子查询**（字段 = `(SELECT max(y) FROM t WHERE …)`） | 本身是字段级值表达式，原样进表达式列；t 作为物理表登记实体级 |
| **多个字段来自同一逻辑从表** | 各自穿透、各自展开，说明段都指回同一锚；片段仍只在实体级一份 |
| **只参与行集、不贡献值的表** | 实体级照常登记（关联条件+片段可见其作用），属性级无引用合法 |
| **物化 tmp（含多层 / 多消费者）** | 内联等价：tmp 的 SQL 作为逻辑从表定义，台账与未物化写法同形；同一 tmp 被多处引用时片段一份、锚名取引用别名 |
| **增量取数条件**（含平台变量，如 `a.etl_dt > ${last_run}`） | 不做特殊处理——还原逻辑，逻辑里有就原样带上；平台变量形态本身就是「调度参数」的显式标记 |
| **初始化管道（init）** | 不做特殊处理——台账还原代码中的逻辑本身，不区分写入管道 |

## 五、贯穿样例

> 表格为**内容示意**，非格式规范。

存量 SQL（制品导出，主表关联一个由三张物理表两次预处理而成的逻辑从表）：

```sql
SELECT m.order_id, m.amount,
       d.final_rate  AS fx_rate,
       d.region_name AS region
FROM dwd.ord m
LEFT JOIN (
    SELECT ab.k, ab.rate * c.adj AS final_rate, c.region_name
    FROM (SELECT x.k, x.rate FROM (
              SELECT a.k, a.rate,
                     ROW_NUMBER() OVER (PARTITION BY a.k ORDER BY b.eff_dt DESC) rn
              FROM ods.fx_rate a JOIN ods.fx_eff b ON a.k = b.k) x
          WHERE x.rn = 1) ab
    JOIN ods.region_adj c ON ab.k = c.k
) d ON m.cust_id = d.k
```

### 实体级（4 条登记，无 d/ab/x 行）

| 源表 | 别名 | 关联&限定条件 | 取数规则 |
|---|---|---|---|
| dwd.ord | m | 主表 | |
| ods.fx_rate | a | 【逻辑从表 d → 主表】`LEFT JOIN d ON m.cust_id = d.k` | 【逻辑从表 d · 定义】`SELECT ab.k, ab.rate*c.adj AS final_rate, c.region_name FROM (SELECT x.k, x.rate FROM (SELECT a.k, a.rate, ROW_NUMBER() OVER (PARTITION BY a.k ORDER BY b.eff_dt DESC) rn FROM ods.fx_rate a JOIN ods.fx_eff b ON a.k = b.k) x WHERE x.rn = 1) ab JOIN ods.region_adj c ON ab.k = c.k`（整段逐字）（按 k 取生效日期最新一条汇率，乘区域调整系数） |
| ods.fx_eff | b | 【d 内】`JOIN ods.fx_eff b ON a.k = b.k`（提供 eff_dt 作去重排序依据，不贡献字段值） | 参与逻辑从表 d（定义见 a 行） |
| ods.region_adj | c | 【d 内】`JOIN ods.region_adj c ON ab.k = c.k` | 参与逻辑从表 d（定义见 a 行） |

### 属性级

| 目标字段 | 源别名.字段 | 映射规则 | 映射表达式 |
|---|---|---|---|
| fx_rate | `a.rate;c.adj` | 数据加工 | `a.rate * c.adj（经逻辑从表 d：a⋈b 按 k 取 eff_dt 最新一条后 ⋈ c；汇率 × 区域调整系数）` |
| region | `c.region_name` | 直取 | `c.region_name（经逻辑从表 d 直取）` |
| amount | `m.amount` | 直取 | `m.amount` |

fx_rate 的展开链（各跳原样、仅代入）：

```
d.final_rate → ab.rate * c.adj → a.rate * c.adj
（ab.rate = x.rate = a.rate，纯直取代入；去重是行集变换，不进表达式，在 a 行片段）
```

若 ab 层是聚合（`max(a.rate) GROUP BY k`）而非开窗去重，则表达式为语义表达式：
`max(a.rate) * c.adj（a 按 k 聚合取最大；经逻辑从表 d）`。

### 物化无关性对照

同一逻辑若实现为物化（两条规则），台账与上面**逐格相同**：

```sql
-- 实现一（物化，两条规则）
R0001: INSERT INTO dws.tmp_fx
       SELECT ab.k, ab.rate * c.adj AS final_rate, c.region_name
       FROM (… ROW_NUMBER() … WHERE x.rn = 1) ab JOIN ods.region_adj c ON ab.k = c.k
R0002: SELECT m.order_id, m.amount, d.final_rate AS fx_rate, d.region_name AS region
       FROM dwd.ord m LEFT JOIN dws.tmp_fx d ON m.cust_id = d.k

-- 实现二（未物化，一条规则）= 第五节开头的 SQL
```

两者台账一致：实体级四张物理表登记、**无 tmp_fx 行**；片段【逻辑从表 d · 定义】挂 a 行
（内容 = R0001 的 SELECT 主体 = 实现二的内联子查询主体）；锚名 d = R0002 引用它的别名；
属性级穿透登记与展开链完全相同。tmp_fx、R0001/R0002、INSERT 方式在台账上零痕迹。

## 六、产出必须满足的可校验性质（自检锚）

1. **引用闭包**：属性级表达式本体（剥除说明段）的全部 `别名.字段` 引用 ⊆ 实体级登记的物理别名集；
   锚名不出现在引用位。
2. **片段逐字性**：每个挂载片段是某一规则 query_sql 的逐字子串（可机器校验）。
3. **展开可回溯**：表达式链上每一跳的原样表达式，能在 ts 草稿对应层 design_logic / query_sql 中找到。
4. **结构一致**：字段清单/类型/中文名、物理源表+别名（各规则并集）与 ts 草稿一致（同源）。
5. **完整性**：存在穿透跳过的中间层（tmp/逻辑从表）而实体级无对应片段挂载 = **不合格**——
   行集变换不允许丢是硬要求。
6. **登记有据**：实体级每条登记在 query_sql 中有对应物理表引用；属性级每个源字段在血缘链上有据。
7. **物化零痕迹**：台账任何位置（登记值/表达式/说明段/备注/片段标签）不出现 tmp 表名、规则编号、
   写入方式。
8. **物化无关同形**（设计验收）：同一业务逻辑的物化实现与未物化实现，产出台账逐格相同——
   逆向侧可用成对样本做对照测试。
