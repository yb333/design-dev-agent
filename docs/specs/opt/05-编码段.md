# 05 · 编码段（优化模式）

> 第5章定稿（v1.8）。范围纪律：**开发只管开发**——测试/验证的实现是第6章（UT）自己的事，本章不设计；coder 的机器约束（SQL 围栏）是产出物审计，属编码段闸门，保留在本章。

---

## 一、coder 的输入与产出

- 输入 = **slice_ts 优化模式切片**：单规则落位信息（挂哪/新列定义/新 JOIN）+ **该规则 baseline SQL 原文** + 硬约束（老列投影一个字符不许动，只许追加新列）。
- 产出 = `etl/{rule_code}.sql`（与 `etl_baseline/` 严格分开——新账旧账不同目录，比对与审计都靠这对目录）。
- coder 不读 baseline_view（设计上下文由切片提供）。

## 二、SQL 级围栏

- **判定算法**（笨标准）：AST 级比对（sqlglot）——旧投影列**逐列结构等价**（忽略格式空白，不做语义等价推断）、仅允许追加新列；FROM/JOIN/WHERE/GROUP BY 的变化**必须与 ts.change 声明一致**（声明了新 JOIN 才许加）；等价改写 = 越界，想改先声明。
- **判定函数住 design-dev-shared（纯函数库，单源）**；**闸门单点在 pipe**（coder 交活后独立跑，审计独立于被审计者——与 designer 的围栏由 pipe 跑同理）；coder 经 check_sql 自测是**可选的工作流习惯**（快速反馈、省回路往返），非强制。
- 失败回路：报错带 `[SQL围栏]` 导航回 coder（恢复旧会话），每规则限 3 轮。
- **回路铁律（v2.2 新增）**：任何产物变化，对应层围栏由 **pipe** 重跑后才进 UT——coder 回路改了 SQL → pipe 重跑 SQL 围栏 + UT；designer 回路改了 ts → fence_check + 闸口①' + 受影响规则的 SQL 围栏 + UT。**围栏永远在 UT 之前**。

## 三、多规则改写：并行，无顺序依赖

跨中间表（R0001 写 tmp 加列、R0002 读 tmp 加列）无先后：**列结构由 ts_v2 统一裁定**，coder 改 R0002 读的是 ts_v2 里 tmp 的列定义，不依赖 R0001 的 SQL 文本。对齐 new-pipe 4b：组内并行发起、各写各的文件、互不读对方产出。

## 四、会话管理与失败回路

- pipe 记 task_id（规则→会话映射）；失败恢复旧会话，不新开。
- 三类分流沿用 new-pipe 纪律：SQL 报错（COLUMN/TYPE/SYNTAX）回 coder；**数据质量类不回 coder**（coder 会用 ROW_NUMBER 消除症状，掩盖根因）；环境问题归人。优化场景的"数据质量类"典型形态（对比检查失败/老列不一致）处置见第6章。

## 五、回刷 SQL 的编码

闸口①'选拔回刷才有：designer 产的 init 规则（derive 自增量规则）→ coder 走**现有 INIT_ 流程**（slice_ts 查 init 段、按 dws-coding SKILL §2.5 derive 适配——源 SQL 改时间范围）。执行与验证归第6章。

## 六、DQ 条件化

RS 优化章节提了新字段 DQ 才调 coder 产 DQ；没提不产（完全跟随输入，无系统兜底）。

## 七、DDL 两形态

- **ALTER 变更单（交付物）**：从 ts_v2.change 生成 `alter_table_{表名}.sql`（一表一文件、可含多列），目标表+中间表各一份。pipe 调的脚本（assemble_ddl 优化模式或独立轻量脚本，住 shared）。老 CREATE 文件不动（历史归历史，变更单归变更单）。
- **全量 DDL 定义（推进档案当前态）**：含新列的完整 CREATE——自建资产基于档案原 DDL 重出；json 入料资产从 ts_v2 生成（类型靠查库回填，用途收窄为生成全量 DDL，不用于建环境）。**生成/重出后与档案原 DDL 做"仅差声明变更"的差异校验（v2.2 新增——生成物也要被审计，防生成器 bug）**。随 v1.7 循环链写回档案。是否进对外交付清单 → 第7章定（已定：仅档案，不对外）。
- 视图类资产（I 视图）加列 = CREATE OR REPLACE VIEW，随 ALTER 制品，细节第7章。
- **开发环境的应用执行（ALTER 落库、验证）归第6章**——本章只管生成。

## 八、dws-coding-opt skill 拆分

对称 dws-design-opt：薄 SKILL（改写模式指引：以 baseline SQL 为底稿加列，不从零写 SELECT + 硬约束表述），知识/工具路径引用 dws-coding（slice_ts/check_sql/pick_fields 不搬家）。agents/dws-coder.md 只加 skill 指针。判据同第4章（互斥/低重叠/演化节奏）。
