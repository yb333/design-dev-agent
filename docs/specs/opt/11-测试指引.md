# 优化场景测试指引（opt-pipe 端到端）

> 目标读者：要动手测优化流程的人。三份输入怎么来、跑什么命令、每步看什么、无库/有库两条路。

---

## 一、输入怎么来（真实格式，2026-08-21 确认）

| 输入 | 怎么造 | 说明 |
|------|--------|------|
| **全量 mapping.xlsx** | 资产最新台账：存量行照抄 + 本次变更行在**备注列**写 `202608版本新增`（新来源表在实体级加行同样备注） | 变更声明的**唯一权威**；旧版本标记行（如 `202603版本新增`）是存量 |
| **RS.md** | 3.3 变更记录表加一行（日期 `2026-08-21`/版本 v2.0/修改内容"优化版本：xxx"）+ 正文写 `202608版本新增需求：{完整口径}` | 版本锚点 = 最新"优化"行日期归一 YYYYMM；日期↔YYYYMM 搭桥（v2.0 序号不参与） |
| **存量表示** | 外部资产首次：逆向侧 `/export-baseline` 产 baseline_v1.json；自建/已优化：不用给（档案/懒归档） | peer agent 文件交接 |

调用：`/opt-pipe {需求包目录} [{baseline_v1.json}]`——目录里全量 mapping + RS 各一份
（分拣规则：唯一 xlsx/md；有冗余文件没关系，脚本忽略并记 manifest）。已备好的现成
baseline_v1：analyzer 仓 `docs/baseline_v1-案例/output/DWB_TRADE_MERGE_D/` 或本仓
`tests/fixtures/opt/baseline_v1_demo_full.json`。

## 二、跑流程

```
/op-pipe {baseline_v1.json 路径或资产名} + {mapping.xlsx} + {RS.md}
```

命令装好（`python install.py`）后从对话触发。逐步骤的人工核验点：

| 步 | 看什么 |
|----|--------|
| 0 入料 | `_internal/` 四件齐（ts_baseline / etl_baseline / baseline_view / exemptions）；exit 2=契约问题（找逆向侧） |
| 1 输入校验 | change_request.json 的 fields 与你标注的一致；冲突/漏标会 question 你 |
| 2-3 设计+围栏 | ts_v2.json 有 change 段；`fence_check` 零违规才到闸口；闸口①'三问（落位/回刷/追加变更） |
| 4 编码+SQL围栏 | `etl/` 产出新 SQL；`sql_fence_check` PASS——可故意让 coder 改老列试试拦截 |
| 5 UT | 无库 → 跳过（闸口②告知）；有库 → `ut_report_opt.md`：冻结列零差异 + INSERT 全过 |
| 6 制品 | `ddl/alter_table_*.sql`、`ddl_full/`、`export/patched/`、`export/patch_notes.md` |
| 7 闸口②'+归档 | 确认后 `archives/{schema}/{资产}/NNN_日期/` 出现 |

## 三、无库快速路（先测骨架）

无数据库时流程走到步骤 4（SQL 围栏）+ 制品 + 闸口②'，UT 跳过。验证的是：围栏三段、
制品 patch、归档链——**优化场景最核心的机器审计不依赖库**。

## 四、两条基线路径都测一遍

1. **json 路径**（外部资产首次）：输入 baseline_v1.json；
2. **档案路径**（自建/已优化资产）：先跑一次 new-pipe（或手工把一次优化的交付物放进
   `archives/`），再跑 opt-pipe 时**不给 json**——验证零组装、豁免表为空（档案语义全在）。

## 五、可以故意踩的坑（验证机器审计）

| 坑 | 预期 |
|----|------|
| mapping 标注"修改" | 步骤 1 拒收"本刀不支持的变更类型" |
| 标"新增"但字段已存在 | 冲突阻断 exit 2 |
| 让 designer 改个存量字段 | fence_check `[围栏]` 拦（越界） |
| 让 coder"顺手优化"老列写法 | sql_fence_check `[SQL围栏]` 拦（等价改写也拦） |
| designer 声明了字段但不落位 | fence 反向拦（漏改） |
| UT 场景：改新 JOIN 让它发散 | 输出对比 FAIL → 闸口问根因 |

## 六、已知限制（测到不要惊讶）

1. 回刷窗口的老列对比**搁置**（闸口②'如实提示回归验证弱于增量窗口）；
2. `load_mode_pending`（subpartition/rpt_item/exchange）：baseline_view 报"写入类型待定"；
3. yml patch 为 round-trip 重写，原注释会丢（patch_notes 有说明）；
4. 语义位（主键/粒度/口径）在 baseline 是空位——by design，不是 bug。
