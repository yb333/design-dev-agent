# 优化场景建设 · 总纲与范围（第0章）

> 优化场景 = 存量资产（多为外部构建、无本体系制品）之上的精确变更交付。本文件是优化场景建设的**大纲 + 第0章范围定稿**，是整个系列的母文档；后续各章讨论定稿后在同目录落盘（01-逆向契约 / 02-baseline组装 / 03-输入与围栏 / 04-设计段 / 05-编码段 / 06-验证段 / 07-制品与收尾 / 08-工程与治理）。
>
> **方法论**：大纲只带原则级结论，不带方案细节；章节讨论与原则冲突时，回本文件修订并在修订记录留痕，不在章节里硬凹；全部章节完成后做整体回顾（跨章接口对齐 / 红线覆盖 / 异常路径 / 测试闭环）。

---

## 一、原则级结论（v1.1）

1. **范围与形态**：优化走独立编排剧本（暂名 opt-pipe.md），器官全部共享（designer / coder / assemble_ts / UT / 三类分流）。切入口 = 新增字段场景。
2. **逆向边界三段式**：物理事实在 analyzer 收口（契约上交付完整，本体系零二次 SQL 理解）；语义不出门（business_key / 粒度 / join_safety / 业务口径，两边都不许脚本伪造）；形状各回各家（rs_input / ts.json 的组装永远在本体系内）。
3. **baseline 真理观**：存量以 baseline 为**认定的**唯一真理——json 路径 = 线上实跑的逆向事实；档案路径 = 档案内容（线上被改过时，供方交 json 是唯一推翻通道，我方不验真）；语义层只对增量部分建立（新字段挂哪 / 怎么算 / 新 JOIN 的 safety）。
4. **红线落法**：变更围栏 = 重写不自主；双跑差异人审 = 语义判断不自主；制品只生成不执行 = 推生产不自主。
5. **资产单元**（v1.1 新增，第0章定）：优化对准**资产**，第一刀 = 单规则组资产；**资产内全管**（含跨中间表链路：中间表加列、多规则改写），**资产外不管**。一个资产对多个规则组（analyze-chain 场景）远期再议。
6. **变更模型可扩展**（v1.1 新增，第0章定）：围栏 / ts change 段 / 差异报告按 **change type 枚举**设计，`add_field` 是第一个枚举值；`modify_field`（口径变更）/ `drop_field` / `add_source` 等未来场景必须能在同一模型上适配，**不允许 add_field 专用硬编码**。整体回顾时专项检查。
7. **回刷原则**（v1.1 新增，第0章定）：增量基线（merge 类）加字段**原则上支持回刷**，回刷进第一刀；优化交付物必须**归档回刷脚本**——存量资产欠的回刷脚本由本次优化补上，交付后不再新增同类欠账。
8. **制品精确修改**（v1.2 新增，第1章讨论定）：优化交付的制品更新（SQL / DDL / 术加 execution_tasks / LTS / DQ）**基于原始制品精确修改（patch），不从 ts 全量再生成**——ts_v2 是设计与验证的中枢，不是制品的再生源。这是"重写不自主"红线在制品层的延伸。原始制品不可得时是**显式缺口**（闸口报告），不是降级为全量再生的理由；契约必须携带 provenance（原始源文件的定位信息）。
9. **审查收敛**（v1.3 新增，第3章讨论定）：机器审计（冻结层比对 + 双跑）是**独立防线**——人全部点通过也拦得住越界；人审项只收**机器判不了的语义判断**，呈现为具体可回答的问题（如"回刷要/不要"），不给全量 diff 墙；**防确认疲劳是闸口设计的硬约束**。变更矩阵每格标注"机器审 or 人审"。
10. **段间职责分离**（v1.8 新增，第5章讨论定）：**开发只管开发，测试归 UT**——验证机制（怎么比、怎么跑、怎么落库）是验证段的设计，编码段不设计也不预设；同理，各章讨论不越界设计别的章节的内容（越界内容移送对应章节问题清单）。

## 二、第一刀范围矩阵

**维度1 · 血缘复杂度**：A 同源直挂 / B 新 JOIN 挂载 / C 跨中间表链路——**全部在范围内**（C 由原则5覆盖：资产内全管）。

**维度2 · 基线写入模式 × 回刷**：
- 全量基线（truncate 类）：下次调度自动补齐新列，无需回刷 ✅
- 增量基线（merge 类）不回刷交付：历史行新列 NULL，闸口①'如实告知，人接受即交付 ✅
- 增量基线回刷：复用 init 双管道机制，人选拔回刷则产回刷脚本 ✅（原则7）

> **依赖标注**：增量基线建模依赖第1章契约确认"增量语义事实的还原度"（delete_condition / 增量变量 / 驱动表哪些可逆向）；确认不足的语义位走人补回路（对齐原则2"语义不出门"），不阻塞机制设计。

## 三、排除清单（第一刀不做）

1. 删字段、改字段口径——属未来 change type（`drop_field` / `modify_field`），非第一刀。
2. 资产外影响——源端变更倒逼目标（impact-analysis 场景）、其他资产消费本资产中间表。逆向信息可得时在闸口报告**提示**，不阻断不处理。
3. 结构类变更——表拆并 / 分区 / 分布键调整。
4. 多规则组资产（analyze-chain 场景，原则5）。
5. DQ——沿用"完全跟随输入"：优化输入提了新字段 DQ 就加，没提不加，不发明系统兜底。

## 四、成功标准（验收案例）

**案例一 · 全量基线，两步链路**：analyzer demo 资产外部化（ods→tmp→dwb），优化输入 = mapping 标注 2 个新增字段——一个同源直挂（A），一个新 JOIN 维表且血缘穿中间表（B+C）。
断言：① 双跑老列逐值一致、新列有值且 NULL 率符合设计声明；② ts_v2 与 ts_baseline 的 diff **恰好等于**变更清单（不多不少）；③ 目标表+中间表各一条 ALTER ADD COLUMN、无 CREATE；调度不变；DQ 按输入条件出现；④ 闸口①'/②'真实停下问人（非交互需显式声明）；⑤ baseline 语义位显式 `_unknown`+豁免，无编造值；⑥ 案例 fixture 化进 tests/（不连库），pytest 全绿。

**案例二 · 增量基线，回刷**：merge 类资产 + 新增字段 + 人选拔回刷。
断言：① 回刷脚本进制品并归档；② UT 按回刷建基线→增量两阶段执行通过；③ 回刷后历史行新列补值、老列不变；④ 闸口①'如实呈现"回刷/不回刷"选项及代价。
> 案例二前置 = 第1章增量还原度确认（或缺口走人补回路的验证）。回刷窗口的老列对比已搁置（v2.2），闸口如实提示回归验证弱于增量窗口场景。

**案例三 · 自建资产，档案路径（v2.2 补；v2.5 修正入口）**：new-pipe 建资产（产出留标准目录）→ opt-pipe 入口懒归档 → 加字段优化走档案路径。
断言：① 入口零 json 零组装（档案直接当 baseline）；② 豁免表为空（语义全在，存量校验不降级）；③ 增量资产回刷可直接复用档案 init 段；④ 其余断言同案例一。

**横断检查**（整体回顾执行）：change type 枚举化（无 add_field 硬编码）；跨章接口一致（围栏↔change 段↔制品增量）；红线四条全覆盖；异常路径（契约缺 key / 人否决 / 回刷被拒 / baseline 本身有病）有处置。

## 五、章节结构与顺序

**0（本文件）→ 1 逆向契约 → 3 输入与围栏 → 2 baseline 组装 → 4 设计段 → 5 编码段 → 6 验证段 → 7 制品与收尾 → 8 工程与治理 → 整体回顾**
（1 排第二因外部时延，讨论稿早发早等；3 在 2 前因围栏表达影响 baseline 保留内容。）

各章要回答的问题：

- **第1章 逆向契约（跨项目，单人双仓）**：契约内容（哪些事实 / 必填可空）；增量还原度（✅ 已勘察解除：load_mode/write_condition/增量变量为可逆事实，增量字段/驱动表为语义位走人回路）；`merge_on` 必供（delete_mode=6 时，实现来源是 analyzer 的自由）；**provenance 段**（原始源文件定位信息，原则8 要求必带；**具体形态开放**——路径清单 / 内容快照 / 混合，待第7章 patch 语义定）；**平台代次**（platform_generation 标注 + 枚举映射表归我方按代次维护，契约只带逐字原始值）；历史回刷/补数任务发现（远期可选，第一刀人回忆）；版本与变更协议；fixture 与双方契约测试（不跨仓 import）；**调用边界（v1.4 定）：文件交接，不跨项目调用脚本**——baseline_v1 由输入侧跑 analyzer 产出并交付，我方 pipe 从契约校验开始；patterns 维持 hint 给人看不进 ts；**warnings 的消费方式开放**（闸口展示 / 参与 patch 决策 / 仅存档——依赖第7章 patch 语义先定，契约携带差异事实本身成本为零、任何政策下都不亏）；消费方不感知 analyzer 的输入模式（xlsx/代码仓之别是生产方的事，契约只有事实+显式空）。
- **第3章 优化输入与围栏**：输入标注格式（RS 章节 / mapping 标记）；变更清单的机器可读表达（按 change type）；围栏判定归属与算法；围栏外变化处置（硬阻断 / 问人）；源端驱动新增是否第一刀支持。
- **第2章 baseline 组装与接入**（v1.7 定稿，见 02-baseline组装与接入.md）：**唯一锚点 = 体系内资产档案**（ts + etl SQL + ddl，交付物全集）。优化循环链 = 读档案（baseline = 档案当前态）→ 增量设计 → ts_v2 → 交付**写回档案**（当前态推进，下次即 baseline）。**json 只是入料**，出场仅两时机：① 无档入料（外部资产首次）；② 有档但供方交 json = 声明"线上被外力改过" → 覆盖重入料（清掉档案攒的语义，第一刀无影响，将来继承时加"结构未变位保留"）。写档案只有两个动作：json 入料 / 懒归档（首优时从 new-pipe 标准产出拉档；new-pipe 无归档步骤）；日常有档优化不需要 json。**历史 = 按次交付目录序列，ts 文件不含历史**。档案持久化存放挂第8章。入口其余沿用 v1.5：流程无断点；不做新鲜度校验（默认输入准确，责任归供方）；mapping 是业务侧交付物（只发布输入格式规格，不做跨 agent 设计）；存量语义第一刀不补（入料路径，双跑兜底）。
- **第4章 设计段（优化模式）**（✅ 定稿，见 04-设计段.md）：skill 拆分（dws-design-opt 薄 SKILL 单线工作流，references/scripts 路径引用不搬家，agents/dws-designer.md 只加 skill 指针；判据"拆工作流不拆资产"）；designer 只写**增量 decisions**（不重写存量），assemble_ts 应用到 baseline 产出**完整 ts_v2 + change 段**（下游工具零改造）；落位决策知识进 opt-playbook；回刷决策表（全量自动补齐/增量闸口①'人选拿）；闸口①'三问（落位确认/回刷选择/建议追加变更，原则9 收敛）；存量豁免自动生成（exemptions.json，走现有豁免机制非重构）、新增全审；共享工具留 dws-design/scripts（按调用方归位，opt pipe 管线脚本才进 shared）。
- **第5章 编码段（优化模式）**（✅ 定稿，见 05-编码段.md）：slice_ts 优化切片（带 baseline SQL 原文）；SQL 围栏（AST 级老列不动+仅追加+变化须与 change 声明一致；判定函数住 shared 单源，**闸门单点在 pipe**、coder 自测可选）；多规则并行（列结构由 ts_v2 裁定）；会话管理与三类分流沿用；回刷 SQL 走现有 INIT_ 流程；DQ 条件化；DDL 两形态（ALTER 变更单交付 + 全量 DDL 推进档案）；dws-coding-opt 对称拆分。
- **第6章 验证段**（✅ 定稿，见 06-验证段.md）：UT 骨架照旧；主键豁免/空值只查新列/**输出对比新增检查项**（双向 MINUS 同数据同时点，oracle 按声明参数化，SELECT 对比+全量 INSERT 互补）；DDL 步骤 CREATE 改 ALTER（表不存在=环境归人）；失败三类照旧（对比失败归数据质量类走 6b 人定根因）；回刷 init→增量现有机制；闸口②'两问（新列合理性+交付物确认）。
- **第7章 制品与收尾**（✅ 定稿，见 07-制品与收尾.md）：交付副本模式（patch 产物=更新后文件副本+patch说明，人不拼 diff、我们不碰仓）；**严格 patch**（只落变更清单，存量声明漂移保留+报告；制品层同样满足"diff 恰好等于变更清单"）；warnings 收口=报告+存档不参与 patch；provenance 收口=路径优先快照兜底；**patch 引擎 = 编辑原语×变更声明**（单元格替换/行追加/行更新/行删除/文件新增/文件删除，change_type 参数化——动作表含未来类型预留行，原则6 落实到制品层）；稳定标识定位+保真铁律；DDL 变更单交付/全量 DDL 仅档案；回刷脚本交付+归档；收尾写回档案（循环链闭合）。
- **第8章 工程与治理**（✅ 定稿，见 08-工程与治理.md）：opt-pipe 剧本（铁律沿用）；档案区入 git（文本小件，xlsx 不进；new-pipe 补归档步骤）；脚本清单按调用方归位（shared 新增 assemble_ts_baseline / fence_check / preprocess_opt / sql_fence / assemble_ddl 优化模式 / artifact_patcher / archive_writer / ut_* 扩展）；文档同步清单；测试不连库；eval 优化用例；install。
