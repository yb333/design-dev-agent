# Mapping 文件格式说明

> 本文档说明 **mapping.xlsx 的 2 个 sheet** 的列定义与填写规范。
> 输入整体结构（mapping + RS 如何组合、rs_input.json 如何生成）见 [rs-input-format.md](./rs-input-format.md)。
> **标准模板**：`docs/templates/mapping模板.xlsx`——与实际业务模板对齐，如有变更同步更新。

---

## 文件结构总览

mapping.xlsx 只包含 **2 个 sheet**：

| Sheet | 名称 | 必须 | 说明 |
|------|------|------|------|
| 1 | 实体级mapping | ✅ | 源表与目标表的关联关系（表级） |
| 2 | 属性级mapping | ✅ | 字段级别的映射规则（字段级） |

> 调度/执行平台/设计配置等信息**不在 mapping**，见 RS 文档。

---

## Sheet 1: 实体级 mapping

定义源表与目标表之间的关联关系。

### 列定义

| 列名 | 必须 | 说明 | 示例 |
|------|------|------|------|
| 序号 | ❌ | 行号 | `1` |
| 分组 | ❌ | 场景分组（默认 default） | `default` |
| 源表schema* | ✅ | 源表所属 schema | `fin_dwl_cnb` |
| 源表中文名 | ❌ | 源表中文名 | `合同pu指标表` |
| 源表物理表名* | ✅ | 源表物理表名 | `dwl_con_pu_mtr_f` |
| 源表别名* | ✅ | 区分同一源表的不同关联实例 | `t`、`f`、`inv_mtr` |
| 目标表逻辑schema* | ✅ | 目标表所属 schema | `fin_dwl_cnb` |
| 目标表中文名 | ❌ | 目标表中文名 | `合同pu分析表` |
| 目标表物理名称* | ✅ | 目标表物理表名 | `dwl_con_pu_any_f` |
| 取数规则 | ❌ | 特殊取数方式说明 | |
| 关联&限定条件 | ❌ | 源表与主表的关联条件，主表填说明 | `left join on t.contract_key = f.contract_key` |
| 备注 | ❌ | 补充说明 | `需排除非洲发票` |
| 数据库类型 | ❌ | 数据库类型（预留） | |

### 源表别名说明

当同一张源表被关联多次（不同关联实例），用别名区分。别名在属性级 mapping 中用于标识字段来源。

---

## Sheet 2: 属性级 mapping

定义字段级别的映射规则：每个目标字段从哪个源字段来、怎么转换。

### 列定义

| 列名 | 必须 | 说明 | 示例 |
|------|------|------|------|
| 序号 | ❌ | 行号 | `1` |
| 分组 | ❌ | 场景分组 | `default` |
| 源Schema | ❌ | 源表schema（可从实体级推导） | `fin_dwl_cnb` |
| 源表物理表名 | ❌ | 源表名（可从实体级推导） | `dwl_con_pu_mtr_f` |
| 源表别名 | ✅ | 对应实体级的源表别名 | `t` |
| 源表字段中文名 | ❌ | 源字段中文注释 | `合同号` |
| 源表字段名 | ✅ | 源表字段名 | `contract_no` |
| 源表字段类型 | ❌ | 源字段数据类型 | `nvarchar(500)` |
| 映射规则* | ✅ | 转换类型分类（**具体分类值待与业务方对齐**） | `直取`、`行转列`、`聚合`（暂定） |
| 映射表达式 | ❌ | **自然语言描述**加工逻辑，**不含业务术语** | `rpt_code='fbt_0001'对应设备订货金额，按合同+pu汇总` |
| 目标字段名* | ✅ | 目标表字段名 | `contract_no` |
| 目标字段中文名 | ❌ | 目标字段注释 | `合同号` |
| 目标字段类型 | ✅ | 目标字段数据类型 | `nvarchar(500)` |
| 备注 | ❌ | 补充说明 | `主键` |
| 数据标准 | ❌ | 数据标准引用（预留） | |

### ⚠️ 映射表达式的填写要求

- **必须用自然语言**，不要写 SQL 表达式（如 `SUM(CASE WHEN...)`）
- **不含业务术语**（预检会校验）—— BA 能看懂的描述，不要用内部黑话
- 描述"算什么、什么口径"，不描述"SQL怎么拼"
- 复杂逻辑（行转列/聚合/多步）必须写说明，简单直取可填"-"

## 优化场景：变更记录页签（v3 格式规范，2026-10-14 与业务侧确认）

优化场景（opt-pipe）消费**全量最新 mapping**（实体级/属性级两页签结构不变，内容 = 当前
需求下最全最新），变更事实放在**第三个页签「变更记录」**——结构化、机器直接可读：

### 八列定义

| 列 | 必填 | 说明 | 示例 |
|----|------|------|------|
| 变更序号 | ✓ | 行序号 | `1` |
| 变更时间 | ✓ | 批次锚点——历史批次**累积**在同一页签，按时间归一 YYYYMM 区分 | `2026-10-14` |
| 变更页签 | ✓ | `实体级` \| `属性级` | `属性级` |
| 变更KEY | ✓ | **列名大小写不敏感**（真实模板为「变更KEY」大写，消费端 strip+lower 归一匹配）。值锚定唯一行：**实体级=`分组\|源表别名`，属性级=`分组\|目标字段名`**；值内标识符也大小写不敏感（DWS=PG 内核 foldcase，归一小写） | `DEFAULT\|CHANNEL_NAME` |
| 变更列 | ✓ | 哪一列的内容变了；**特殊值 `资产字段` = 整行新增**（新字段/新来源，不逐列列举） | `资产字段` / `映射表达式` |
| 变更类型 | ✓ | `MODIFY` \| `ADD` \| `DELETE` | `ADD` |
| 变更前 | ✓(可空) | 变更前的值 | |
| 变更后 | ✓(可空) | 变更后的值 | |

### 变更语义

- **改名 = 先删后加两行**（变的列是"目标字段名"时）：DELETE 行（key=旧字段名）+ ADD 行
  （key=新字段名），**两行 key 不一样（删旧加新）**；消费端合成判定 = DELETE 行的
  「变更后」指向 ADD 行的 key（严格证据链，证据不成立则各自独立归类）；
- **独立 ADD/DELETE**（非成对）= 独立的新增/删除；属性级整行新增（变更列=`资产字段`）
  = 新增字段；实体级 ADD = 新来源；
- **列级变更**（变更列=具体列名，如映射表达式/备注）= MODIFY（或对已有字段的列级 ADD）；
- **消费支持度**：属性级整行 `ADD`（`资产字段`）与 `MODIFY`（目标字段类型/映射表达式）全流程支持；rename/
  DELETE/实体级 ADD/列级 ADD → **识别归类、报告"待扩展"**，不是非法值；
- **本次批次** = 页签内最新变更时间归一 YYYYMM（默认；可 `--version` 显式重选历史批次）；
  实体级/属性级当前态页签中不在 baseline 且不在本次变更记录的字段 → warn 漏标提示
  （台账漂移防线）；
- RS 职责不变（DQ/调度/回刷意向等需求侧信息仍在 RS），RS 表格加"变更记录"列区分本次
  内容——**变更事实主源在 mapping**，RS 为口径材料。

> 历史：曾设计"变更标识"专用列（枚举：新增/空），2026-08-21 按当时真实格式改为备注列
> 版本标记（`{YYYYMM}版本{动词}`）；2026-10-14 业务侧升级为「变更记录」结构化页签
> （v3，当前规范），备注列标记格式废弃。
