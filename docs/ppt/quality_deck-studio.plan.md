# 质量保障分享 deck · 页面规划（quality_deck-studio.html）

> 主题：AI for IT 分享——开发环节（含 IT 设计）的质量保障实践。
> 从《技术评审》deck（tech-review_deck-studio.html，13 页项目全景）抽出质量主线，重组织为 7 页方法论叙事。
> 视觉沿用 yunshan 品牌模板 + 蓝色三层主题 + deck-studio 引擎（封面/结束页 base64 资产原样搬运）。
> **视觉定调（用户要求）：少卡片、多图**——阶梯图/管线闸门/判定树/流程图承载内容，不做卡片阵列。

## 需求共识

- 听众：AI for IT 横向受众（懂 IT 不熟本项目），带着的疑问 =「AI 干开发的活，质量怎么敢用？」
- 目标：离场记住三句话——**能算的让脚本算 · 能修的让 AI 修 · 该裁的让人裁**
- 核心隐喻（与用户讨论定稿）：三层防线是**递进关系**——受理范围/处置能力递增，确定性来源/成本效率反向；设计原则=拦截尽量前移，人只花在语义终裁
- 约束：7 页（封面+5 内容+结束），每页信息密度高；黑话清零（横向受众）；数字全实测不编造；诚实边界主动交代

## 三道防线的递进逻辑（deck 骨架隐喻）

- **防线① 确定性脚本**：只判"可结构化的对不对"；100% 可复现；秒级零成本；拦截占比最大
- **防线② 有边界的自治**：修"技术性失败"（旧会话恢复+≤3 轮+修完必重验）；先脚本定位再动手；告警零自动回路
- **防线③ 人守闸口**：裁"语义/放行/表外一切"；红线约束+留痕；触点收敛到两个闸口
- 移交规则写在层间箭头上，**按问题性质路由不是层层漏**：L1 检出即分诊——技术可修的进防线②，决策/语义类直达防线③
- 防过度的本质：**结构性限位**（轮次上限/职责白名单/变更必回闸口/告警零迭代/按表路由），不是提示词恳求

## 四类翻车 ↔ 防线对位（P2 呼应关系）

| 翻车 | 真实案例 | 死在哪 |
|---|---|---|
| 幻觉引用 | 引用不存在的字段/表 | 防线① 引用门禁+连库核验 |
| 口径漂移 | 删除标记被转述成空串条件、语义反转（实测教训） | 防线① 表达式原样保留+口径对账 |
| 静默错位 | 按位置对齐的 INSERT 列序乱序 | 防线① 数据库实测列序对账 |
| 掩盖根因 | 去重技巧（ROW_NUMBER）消掉报错反而丢数据 | 防线② 先定位 + 防线③ 裁决 |
