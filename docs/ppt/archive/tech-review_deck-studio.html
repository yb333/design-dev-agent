数据交付 Agent：设计开发段技术实现与架构
日期：2026.09
作者：数据交付 Agent 项目组
云山
01 / 背景
设计开发段：重做功、重经验，agent 接管「做」，人守住「判」
整套体系基于公司 codeagent 平台（agent 运行环境）搭建：接 BA 的《RS》+《mapping》，交设计文档与四件套制品——替代今天一段段的人肉工序。
02 / 形态
一条流水线八道工序，人只在两个闸口出手
吃 RS+mapping（需求 spec + 字段映射），吐 TS + 四件套制品。UT 直连开发库两阶段收尾，代码稳定后交付下游。
03 / 流转
一条主链五条回路：失败回岗，人判在闸口
动画即运行语义：光点沿主链流转；三类失败按根因打回对应岗；两个闸口人判——不收就打回重做。
04 / 编排
编排岗加三个专业岗：职责边界写进权限，问题沿路由上交
一个编排岗（engineer）起三个专业岗（designer / dq-producer / coder），Task 直连；每个岗只能写自己的产物，越界落不了盘。
05 / 校验
AI 生成、脚本把关：五道确定性校验贯穿全程
质检独立性来自「生成者 = LLM，把关者 = 确定性脚本」——同一脚本跑两遍结果必然相同，收卷对账即可，不重验。
06 / 场景
新建与优化共用一条主干，优化只精确修改
差异只在入口材料。优化场景已建成：档案做底本、围栏守边界、影响分析定重做范围——变更恰好等于声明。
07 / 分流
失败按根因找岗：SQL 回 coder，数据质量退设计
分流判定树：每类失败按识别特征路由到唯一归宿，轮次有限——告警不进自动迭代，方案在人手里。
08 / 协同
对外靠 spec 交接，对内靠 直连
对上下游只交接 spec；总控 Task 直连编排岗，数据库脚本直连——MCP 全线禁用；每个平台是制品的目的地。
09 / 成果
全链路能力建成：五层实现、一套技术底座
五层实现：编排剧本、agent 岗位、知识包、确定性脚本、公共设施——每一件都在工具注册表和测试守护下。
10 / 价值
价值收益：一周多的设计开发，1~2 天交付
内部口径（试点观察）：机器产出 ≤1 小时，端到端 1~2 天——含 SE 需求口径对接、开发评审与测试；量化评测以平台独立报告为准。
11 / 进展
主干已在codeagent 平台真实案例运行，验证与扩充在继续
三栏看状态：建成即用、真环境验证、下一步清单——每项都有明确判据，不写愿景。
