01 / 定位
定位：DDLC 中游主力段，三条红线定边界
数据交付全流程的"设计开发"段。一个 agent 系统连续完成「设计→编码→UT」，人只在闸口拍板。
02 / 全貌
全貌：四区结构，块间靠契约交接
主体能力产 TS+代码，制品能力产平台中间表达，评测体系离线验证，编排层串联。块间解耦，可独立分工。
03 / 核心过程
核心过程：从 RS 到可跑的代码，一条主干
预处理 → designer 产 TS → 闸口① → coder 按规则编码（螺旋）→ 导出。大表按规则分段，规模自适应。
04 / 核心产出
TS 制品包：以规则为核心，ts.json 机读 + ts.md 人读
TS 不是单文档，是制品包。规则是核心实体，场景是属性。字段内嵌规则，按 rule_code 切片，coder 按规则读取。
05 / 技术架构
技术架构：command 是任务单，agent 是执行者
项目不是"一个 agent"，是"agent 系统"。orchestrator 持共用知识，command 注入任务流，子agent加载各自的skill。
06 / 能力边界
螺旋回路：当前残缺，但保留扩展空间
只有开发环境数据库打通。段1自动闭环，段2/3当前人工。术加2.0支持MCP后无缝接入——过渡状态，非长期前提。
07 / 质量保障
质量保障：层层把关，不通过回最近产出者重做
AI 产出本质不稳定。每个关键产出后有检查点，越靠后确定性越强（脚本/人判）。段内是流程 gate，段外是改进闭环。
